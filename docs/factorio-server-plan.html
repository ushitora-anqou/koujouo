Hosting Factorio Servers in koujouo

Why · 5 requests koujouo は Factorio https://www.factorio.com/ の headless サーバーを Kubernetes 上でホストするための Kubernetes controller である。koujouo は FactorioServer CRD を導入する。 agent の Docker image には Factorio のゲームバイナリを埋め込まない。これはライセンスの観点からも有用である；これにより agent の Docker image は public registry から配布できる。また同様にゲームの設定なども ConfigMap 経由ではなく Cap'n Proto 経由で渡す。 Factorio のログにはユーザーがサーバーに join/leave したことを示す出力が行われるため、これを見て join/leave を Discord に通知する。 agent は Factorio サーバーを停止する際には優雅に停止させる。…1. サーバー内にプレイヤーが join しているかを確認する。join している場合は rcon を使ってメッセージを送り、サーバーが停止するので退出するよう求める。2. プレイヤーがいなくなったら SIGINT を送る。…3. プレイヤーが全員退出していない場合でも、メッセージの送信から .spec.leaveTimeout 時間だけ待機したら 2 を実施する。 CNPG を参考にし、agent の Docker image を更新する際に Factorio server を止めずに行えるようにする。これは controller から agent にプロセスバイナリを Cap'n Proto で送りつけたうえで agent がそのバイナリに exec(2) することで行えるはず。

Each stop waits for the players, then writes the save.

The agent warns the players, then sends SIGINT to Factorio.

rcon binds to 127.0.0.1 with a random password; no Service exposes it. Factorio writes the save file, then exits with code 0. Pod stop kubelet sends SIGTERM to the agent. The agent answers with this same path, never a fast exit.

The controller never deletes the claim.

  • The kubebuilder layout and the Nix flake stay. Follow AGENTS.md.

  • rcon stays inside the pod. The old rcon Service goes.
